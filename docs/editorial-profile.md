# Editorial profile

This project uses an ASD-STE100-inspired editorial profile for clarity. It
does not claim compliance with ASD-STE100. It does not copy or reproduce the
standard.

Authors SHOULD:

- use one idea per sentence;
- use a familiar term consistently;
- prefer direct, active instructions;
- define a term before using it as a requirement;
- state limits and failure behavior explicitly;
- keep examples synthetic and testable.

Authors SHOULD avoid:

- marketing claims in normative text;
- unexplained abbreviations;
- vague verbs such as "handle" when a specific action is known;
- hiding security or compatibility limits in implementation notes.

The specification uses uppercase requirement terms only when a rule is
normative. Narrative text may describe intent without creating a protocol
requirement.
